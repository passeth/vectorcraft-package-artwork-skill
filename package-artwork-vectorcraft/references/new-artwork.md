# 신규 제작 (new 모드): 시안 이미지 → 인쇄 데이터

첫 시범: 500ml 원통 용기의 용기인쇄(디자이너 시안 PNG → 230×120mm 2도 벡터).
결과물은 **디자이너 검토용 초안**이다. 로고·아이콘 원본과 실제 폰트로 바꾸기 전에는 최종 인쇄 데이터로 보내지 않는다.

## 받아야 하는 것 (빠지면 질문한다)

| 항목 | 없을 때 |
|---|---|
| 시안: 평면 레이아웃 이미지(디자이너 PNG/PDF가 가장 좋음) | 3D 목업만 있으면 곡면·원근 왜곡이 있어 평면 배치는 추정이 된다고 알린다 |
| 인쇄 영역 크기(mm), 금지 영역 | 300ppi 시안이면 픽셀로 잰 값을 제안하고 확인받는다(예: 2716×1417 px → 229.95×119.97 mm) |
| 인쇄 방식·도수·색(PANTONE 번호, 백색 여부) | 시안의 컬러칩·메모에서 읽고 확인받는다 |
| 로고·심볼 원본 벡터(AI/SVG) | 시안에서 트레이스한 초안으로 만들고 "교체 필요"로 표시한다 |
| 폰트 이름·파일 | 비슷한 폰트로 맞추고 사용 폰트표를 보고서에 남긴다 |
| 문구 원문(전성분 docx 등) | 이미지에서 읽은 문구는 원문과 대조 전까지 미확정으로 표시한다 |
| 바코드 번호 | 시안 숫자를 읽고 체크디지트로 검증한다 |

공유 드라이브에서 같은 제품의 디자이너 결과물(QC 폴더 등)을 먼저 찾는다. 시범에서는 사용자가 준 목업 대신 디자이너의 용기인쇄 시안 PNG가 있어 그것을 기준으로 삼았다.

## 절차

1. **작업 폴더**: `new_job.py --mode new --name … --source <시안> --ref <전성분.docx> --item "<결정 사항>"`.
2. **측정**: 시안이 300ppi면 1px = 0.24pt로 1:1. `layout_kit.Ref(path, ppi, background=<바탕색>)`.
   - `ref.rows(box)`로 줄(띠)을 찾고, 넓은 간격으로 요소를 나눈 뒤 `ref.tight(box, test)`로 잉크 박스를 잰다.
   - 색 구분: 예) 크림(7499C)은 `R−B > 20`, 흰색은 그 외.
   - 원통 용기는 전면 중심 = 둘레의 ¼, 후면 = ¾인지 확인한다(시범: 57.5 / 172.5 mm, 단 폭 60 mm).
3. **문서**: 시트 크기 그대로 `file.new {width, height, colorMode:"cmyk"}`, 단위 mm.
   - 별색 스와치(`swatch.new {spot:true}`): 판 이름 = 스와치 이름(예: `PANTONE 7499 C`, `WHITE INK`).
   - 레이어(아래→위): `00_참고 시안(템플릿·비인쇄)`(시안 PNG를 `rect`로 1:1 배치), `01_용기색 참고(인쇄 아님)`, 판별 레이어, `04_작업 정보`.
4. **로고·아이콘**: `ref.mask(box, path, test)` → `Doc.trace(path, rect, swatch)` (Logo 모드). 같은 로고의 작은 사본은 큰 쪽을 복제해 `object.setBounds`로 맞춘다.
5. **문자**: `Doc.fit_text(text, font, style, ref.tight(box), swatch, size)` — 잉크 높이로 크기, 폭은 자간(−30보다 좁아야 하면 장평)으로 맞춘다.
   - 같은 스타일 쌍(예: 막대 그래프 아래 왼쪽·오른쪽 라벨)은 크기를 하나로 통일하고 폭만 맞춘다(디센더 때문에 크기가 달라진다).
   - 국문 한 줄은 자간 −25 + 장평으로 맞춘다(시안이 장평을 줄인 경우가 많다: 시범 84~96%).
6. **본문 문단**: `Doc.paragraph(lines, target, font, size, leading, last_lines, bold)` — 시안 줄바꿈 그대로, 마지막 줄만 왼쪽 정렬.
   전성분은 줄을 이어 붙인 결과가 docx 원문과 같은지 `assert`로 확인한다. 본문 크기가 5 pt 이상인지 확인한다.
7. **바코드**: `Doc.ean13(code, x, top, module, height, swatch)`. 시안 막대와 상관(극성 두 가지)으로 모듈·시작점·극성을 맞춘다.
   **GS1 최소 80%(모듈 0.264 mm) 미만, 밝은 막대(반전)**면 스캔 위험으로 보고한다(시범: 53.5%, 흰색 막대).
8. **비교**: `ref.compare(box, 03_work/check, label)` — 시안 | 결과 | 차이(빨강). 차이가 글리프 모양뿐인지 본다.
9. **판 확인**: `document.inspect`로 판 레이어의 모든 객체 칠이 해당 별색뿐인지 센다(시범: WHITE INK 83/83, 7499C 6/6).
10. **출력·검증**: 참고 레이어 숨김 → `.ai` 저장, 미리보기 PNG, 아웃라인 PDF → `verify_print_pdf.py --expect-spots "…"`,
    `render_pdf.swift`로 PDFKit 렌더 확인. 보고서 `04_output/제작보고서_v01.md`에 대체 폰트표·트레이스 목록·확인 필요 사항을 적는다.

작업별 빌드 스크립트는 `03_work/build_*.py`로 남긴다(다시 실행 가능한 기록). 시범 작업의 스크립트가 예시다.

생성 AI 시안(목업 이미지)만 있는 경우는 [ai-concept-to-film.md](ai-concept-to-film.md)를 따른다(용기 펼침, 다시 조판, 전성분 근거 특장점, 자리 표시).
