# 작업 폴더 구조

작업 하나(요청서 한 건, 부자재 하나)마다 폴더 하나를 만든다. `scripts/new_job.py`가 이 구조를 만들고 요청서를 읽어 `03_work/job.json`을 채운다.

## 작업 루트

- 기본값: `~/project/부자재작업`. 사용자가 다른 곳을 원하면 `--root` 또는 환경변수 `ARTWORK_JOBS_ROOT`로 바꾼다.
- VectorCraft 자동화의 읽기·쓰기 루트를 **작업 폴더 하나**로 제한해서 실행한다. 다른 작업의 파일은 열 수도, 덮어쓸 수도 없다.

## 작업 폴더 이름

```
<요청서번호 또는 YYMMDD>_<제품코드>_<제품명>_<부자재>
예) 260101-1_ABC001_샘플수분크림50ml_튜브
```

- 요청서번호가 없으면 오늘 날짜(YYMMDD)를 쓴다. 신규 제작이면 끝에 `_신규`를 붙인다.
- 공백과 `/ : * ? " < > |`는 빼고, 제품명의 공백은 붙여 쓴다.

## 하위 폴더

```
<작업 폴더>/
  00_request/   요청서(xlsx), 붙여넣은 요청 문구(request.md), 참고 스크린샷·시안 이미지
  01_source/    원본 .ai/.pdf — 읽기 전용으로 취급하고 절대 덮어쓰지 않는다
                (신규 제작: 로고 벡터, 다이라인·인쇄영역 도면, 규격서)
  02_fonts/     이 작업에 쓴 폰트 파일 사본 (라이선스 있는 폰트만)
  03_work/      job.json(진행 기록), 렌더 비교 이미지, 중간 산출물
  04_output/    납품 파일
```

## 납품 파일 이름 (04_output)

차수(v01, v02 …)를 붙이고 이전 차수는 지우지 않는다.

| 파일 | 이름 |
|---|---|
| 수정본 (텍스트 살아있음) | `<원본파일명>_수정_v01.ai` |
| 인쇄용 (텍스트 아웃라인) | `<원본파일명>_수정_v01_인쇄용_아웃라인.pdf` |
| 미리보기 | `<원본파일명>_수정_v01_preview.png` |
| 변경 보고서 | `변경보고서_v01.md` |

신규 제작이면 `<원본파일명>` 자리에 `<제품명>_<부자재>`를 쓰고 `_수정`을 `_신규`로 바꾼다.

## job.json

`new_job.py`가 만들고, 단계마다 에이전트가 갱신한다. 다음 차수 작업이나 다른 에이전트가 이어받을 때 이 파일부터 읽는다.

```json
{
  "schema": 1,
  "mode": "revision",
  "request": {"no": "260101-1", "productCode": "ABC001", "productName": "…", "component": "튜브",
              "author": "…", "items": ["전면 제품명 국문 글씨체 변경 : 서체 A -> 서체 B"]},
  "extraItems": ["후면 아이콘 제거, 마크 가운데 정렬 (메일로 받음)"],
  "source": "01_source/<원본>.ai",
  "importMode": null,
  "fonts": [],
  "changes": [],
  "outputs": [],
  "verification": [],
  "openQuestions": []
}
```

- `extraItems`: 요청서에 없지만 채팅·메일로 받은 수정 사항. 출처를 함께 적는다.
- `importMode`: `editingData` 또는 `pdfPart`, 고른 이유.
- `changes`: 객체 id, 전/후 값(폰트·자간·좌표), 근거(예: 원본 PDF의 `-0.03 Tc`).
- `verification`: 어떤 방법으로 무엇을 확인했는지, 확인하지 못한 것.
